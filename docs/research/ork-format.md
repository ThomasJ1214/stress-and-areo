# Research: ork-format

> **Topic:** OpenRocket .ork file format (OpenRocket 23.09 = format 1.9, 24.12 = format 1.10; notes on ≤1.8 and 26.xx = 1.11): container, schema, positioning and "auto"-dimension rules, flight configurations, motors, simulations, a working stdlib parser, and whether stored simulation data can be used for cross-validation

_Generated from a hands-on feasibility research agent (2026-10). Items marked VERIFIED were run/read by the agent; others are from recall and must be re-checked before relying on them._

## Recommendation

Build the .ork importer as a geometry and mass model, not a field copier. Read the container (ZIP whose first entry is rocket.ork, legacy GZIP, or plain XML), then re-derive every position, length and "auto" dimension using OpenRocket's own rules: the axial-method formulas, the auto-radius neighbour chain, ring radii taken from the parent's inner radius, mass-object volume preservation, and mass overrides. Do not trust the number stored after "auto": it is a cached value from save time and is stale in 155 of 252 cases in the official samples, including the 24.12 "Dual parachute deployment" example. Keep both the file value and the recomputed value and show a warning when they differ. Offer an "OpenRocket-identical" mode that reproduces OR's load-time position quirk for mass objects with an automatic packed radius. Use the component `<id>` UUID (format 1.9+) as the stable key for CAD-replacement mapping; files at 1.8 or older have no IDs, so use the tree path plus index there. For round-tripping a CAD-replaced part back to OpenRocket, write `overridemass` / `overridecg` / `overridecd`. Write files at format 1.10; plain XML is accepted by OpenRocket, but use valid material group names and explicit densities. All values internally in SI; convert degrees to radians at the boundary (component angles, cant, launch-rod angle and direction). Wind directions are already in radians, and latitude/longitude stay in degrees.

Motors: 23.09 and 24.12 files store only a reference (manufacturer, designation, MD5 digest, dimensions, delay), not the thrust curve. Ship an offline snapshot of thrustcurve.org RASP/RSE files and match by digest using the Python port in motor_digest.py. It reproduced the stored digest for all 7 of the 31 sample motors I tested, plus 4 of 5 curves embedded in 1.11 files. Fall back to manufacturer + designation with a visible warning, and read embedded thrustcurves/*.rse entries in 1.11 files first.

Cross-validation: treat simulation data stored in .ork files as an "OpenRocket estimate" tier, not reference truth. It is rounded to 3 decimals (4 significant figures outside 0.001–10⁴), the turbulence random seed is not saved, and recovery deployment is instantaneous, so post-deployment acceleration spikes are model artefacts rather than shock loads. Stored data is still good for importer regression tests: my parser matched stored dry mass in 182/182 simulations, CG within 2 mm in 142/142, and reference length in 197/197. For full-precision validation, run the official OpenRocket-24.12.jar headless (Java 21, GPL, used as a separate executable) in CI via the verified ORProbe approach. It gives exact structure mass, CG, CP, CNα, reference length and trajectories per configuration (set turbulence to 0 or fix the seed), and can be combined with synthetic geometries whose answers are known exactly.

## Key findings

- CONTAINER [VERIFIED-SRC GeneralRocketLoader/Saver @24.12 + VERIFIED-RUN]: OpenRocket detects the format by magic bytes. (a) 'PK' = ZIP: the loader reads ONLY the first entry (ZipInputStream.getNextEntry once) and only if its name matches *.ork|*.rkt|*.cdx1. 23.09/24.12 always write 'rocket.ork' as the first entry, then decal images under their DecalImage name (e.g. decals/BodyStripe.png); compression level 9. (b) 1f 8b = GZIP of the XML (pre-13.04 files, e.g. simplerocket.ork, format 1.2). (c) Otherwise plain XML: OR looks for '<openrocket' in the first 300 bytes; plain XML is still loadable (asimple.ork 1.4, apocd.ork 1.6, and my synthetic plain file loads in 24.12). The 'Parallel booster staging' sample has zip entries with a LEADING SLASH ('/datafiles/textures/balsa.jpg'), so guard against zip-slip. 26.xx (format 1.11) adds preview.png and thrustcurves/<md5digest>.rse to the zip.
- VERSIONS [VERIFIED-SRC fileformat.txt, DocumentConfig.SUPPORTED_VERSIONS]: the root element is <openrocket version='1.10' creator='OpenRocket 24.12'>. 23.09 writes 1.9 (adds <id> UUIDs on every component; event 'source'). 24.12 writes 1.10 (structured warnings with priority, <docprefs>, <wind model=average|multilevel>, <windmodeltype>, <maxtime>, <designtype>, <kitname>; also seen in source: group= attribute on materials, <launchintowind>, <winddirection>, <separationaltitude>, new separation events altitudeascending/apogee/altitudedescending). The 24.12 loader accepts 1.0–1.10 and attempts newer versions with a warning; it loaded all 1.11 samples. Older milestones: 1.4 = 12.03 (motor digest algorithm changed; digests in files <1.4 are ignored), 1.6 = 13.04 (appearances/decals, so ZIP; per-configuration recovery/ignition/separation), 1.7 = 15.03 (extensions, tube fins), 1.8 = 22.02 (railbutton, podset, parallelstage, overridecd, stage activeness, isflipped; renamed fincount→instancecount, position→axialoffset, rotation→angleoffset, with the OLD NAMES STILL WRITTEN as duplicates). 1.11 (26.xx dev) adds embedded .rse motors, 6-decimal flight data, stable save keys in databranch types=, gravity model, drag/stability lookup CSVs, landingdispersion, plotappearance, simulationsteppermethod, auto line length for parachutes/shock cords; master source also adds a shearModulus attribute on materials and <isdrogue>. Java package renamed net.sf.openrocket → info.openrocket.core; 24.12 rewrites extension IDs on load.
- DOCUMENT STRUCTURE: <openrocket> contains <rocket> (one; later ones ignored), optional <datatypes> (custom expressions: <type source='customexpression'><name/><symbol/><unit unittype='auto'/><expression/>), <simulations>, <photostudio> (1.8+), and <docprefs> (1.10+: <pref key type=string|integer|double|boolean|list>, plus <docmaterials><material>BULK|name|density|group</material>). Components nest via <subcomponents>. Unknown elements produce a warning and are ignored, so the loader is lenient. Enum XML values are always name().toLowerCase() with underscores removed.
- COMPONENT TAGS (23, from DocumentConfig.constructors): external = nosecone, bodytube, transition, trapezoidfinset, ellipticalfinset, freeformfinset, tubefinset, launchlug, railbutton; internal = engineblock, innertube, tubecoupler, bulkhead, centeringring, masscomponent, shockcord, parachute, streamer; assemblies = stage, parallelstage (22.02 betas used 'boosterset'), podset; plus the root rocket. Common elements, in save order: name, id (1.9+; absent in ≤1.8, where OR generates random IDs), preset (type/manufacturer/partno/digest attributes; explicit values later in the file override the preset), appearance (<paint r g b a/>, <shine>, <decal name rotation edgemode=REPEAT|MIRROR|CLAMP|STICKER> with <center>/<offset>/<scale>), insideappearance, color, linestyle, instancecount (+ legacy fincount), instanceseparation, radiusoffset method=coaxial|free|relative|surface, angleoffset method=relative|fixed|mirrorxy (DEGREES; legacy duplicate <rotation> or <radialdirection>), axialoffset method=absolute|top|middle|bottom (+ legacy <position type=…>; NOT written when the method is AFTER), overridemass+overridesubcomponentsmass, overridecg+overridesubcomponentscg (m from component front), overridecd+overridesubcomponentscd (pre-1.8 used a single 'overridesubcomponents' flag), comment. External components add <finish> (roughness: rough 500 µm, roughunfinished 250, unfinished 150, normal 60, smooth 20, optimum 5, polished 2, finishpolished 0.5, mirror 0) and <material type=bulk>.
- PER-COMPONENT ELEMENTS (lengths in m) [VERIFIED-SRC savers + VERIFIED-RUN, elements observed per type in out/schema_observed.txt]. nosecone: length, thickness (m or 'filled'), shape (conical|ogive|ellipsoid|power|parabolic|haack), shapeclipped (nose cones are never clipped), shapeparameter, aftradius (= BASE radius, may be 'auto <cached>'), aftshoulder{radius,length,thickness,capped}, isflipped (if true, base and shoulder move to the fore end). transition: the same plus foreradius/aftradius (either may be 'auto <cached>') and foreshoulder* / aftshoulder*. bodytube: length, thickness|filled, radius ('auto <cached>' allowed), motormount. fins (common): thickness, crosssection (square|rounded|airfoil; volume factors 1.00/0.99/0.85), cant (DEG), tabheight, tablength, tabposition (written TWICE with relativeto= front|center|end and top|middle|bottom), filletradius, filletmaterial. trapezoidfinset: rootchord, tipchord, sweeplength, height. ellipticalfinset: rootchord, height. freeformfinset: <finpoints><point x y/>. tubefinset: radius ('auto' with NO value, or a number), length, thickness. launchlug: radius, length, thickness. railbutton: outerdiameter, innerdiameter, height, baseheight, flangeheight, screwheight. innertube: length, radialposition, radialdirection (deg), outerradius, thickness, clusterconfiguration (single|double|3-row|4-row|3-ring|4-ring|5-ring|6-ring|3-star|4-star|5-star|6-star|9-grid|9-star), clusterscale, clusterrotation (deg), motormount. tubecoupler and engineblock: outerradius ('auto' with no value, or a number), thickness. centeringring: outerradius/innerradius (each 'auto' or a number). bulkhead: outerradius. Mass objects: packedlength, packedradius ('auto <cached>'), radialposition, radialdirection; masscomponent adds mass (kg) and masscomponenttype; shockcord adds cordlength and a LINE material; parachute adds cd ('auto' = 0.8), a SURFACE material, deployevent/deployaltitude/deploydelay, deploymentconfiguration*, diameter, linecount, linelength, linematerial; streamer adds striplength and stripwidth (auto cd = min(0.034·((ρ+0.025)/0.105)·(L+1)/L, 0.4)). stage: separationevent, separationaltitude, separationdelay, separationconfiguration* — never written for stage 0. podset/parallelstage: instancecount, radiusoffset, angleoffset, axialoffset.
- MATERIALS [VERIFIED-SRC MaterialSetter]: <material|filletmaterial|linematerial type='bulk|surface|line' density='ρ' group='Metals|Woods|Plastics|Fabrics|PaperProducts|Foams|Composites|Fibers|ThreadsLines|Other|Custom'>name</material>. Density is ALWAYS explicit SI (kg/m³, kg/m², kg/m), so mass needs no material database. An invalid group falls back to Custom with a warning (verified by loading my synthetic file in OR). 23.09 has no group attribute. The file holds NO structural properties (no modulus, no strength); 26.xx adds only shearModulus. Structural analysis needs its own material library.
- AXIAL POSITIONING [VERIFIED-SRC RocketComponent.setAxialOffset/setAfter + AxialMethod; VERIFIED-RUN, max error 0 m against OR across 1499 components apart from 6e-5 m on canted fins]. Frame: x along the axis, +x aft, x = 0 at the rocket front; position = front of instance 0 relative to the parent's front. With L = own getLength(), Lp = parent length (0 if the parent is the rocket) and off = stored offset: AFTER: x_rel = x_rel(prev sibling) + L(prev sibling), or 0 for the first child (OR skips previous siblings that are inactive in the selected configuration). TOP: x_rel = off. MIDDLE: x_rel = off + (Lp − L)/2. BOTTOM: x_rel = off + (Lp − L). ABSOLUTE: x_rel = off − x_abs(parent). Snap |x| < 1e-6 to 0. x_abs = x_abs(parent) + x_rel. The default method when no axialoffset/position element exists is AFTER; mass objects are never AFTER. Assembly (stage/podset/parallelstage) length = Σ length of children whose method is AFTER. getLength(): body components, tube fins, lug and rings = <length>; trapezoid/elliptical fins = rootchord; freeform fins = x_last − x_first; mass objects = packedlength (see the auto rule); RAIL BUTTON = 0. Stage numbers = depth-first pre-order over stage/parallelstage elements starting at 0; a component's stage is its nearest stage ancestor.
- INSTANCES AND RADIAL/ANGULAR PLACEMENT [VERIFIED-SRC getInstanceOffsets]. Fins: φ_i = φ0 + 2πi/n with φ0 = angleoffset (deg→rad); offset = Rx(φ_i)·Cant·(0, r_body(x_front), 0), cant rotation about x = L/2. OR's reported x includes (L/2)(1 − cos δ) for canted fins (60 µm at 4°), with no CG effect. Tube fins: same angular distribution; auto outer radius = r_b if n < 3, else r_b·sin(π/n)/(1 − sin(π/n)). Launch lug / rail button: instance i at (i·s, r cos θ, r sin θ), with r = parent radius + lug radius (lug) or parent radius (button). Centering rings / bulkheads: instance i at (i·s, 0, 0). Inner-tube cluster: unit-spacing points (from ClusterConfiguration.java, copied into proto_parser CLUSTERS) rotated by (clusterrotation − radialdirection), scaled by 2·r_o·clusterscale, plus (r cos ψ, r sin ψ) from radialposition/radialdirection. Pod set / parallel stage: instance i at (0, R cos θ_i, R sin θ_i), θ_i = θ0 + 2πi/n, where R = off (FREE), off + r_parentBodyTube + r_bound (RELATIVE), r_parentBT + r_bound (SURFACE), or 0 (COAXIAL); r_bound = max outer radius of the child body tubes and transitions. Angle method RELATIVE: θ = θ_parent + off; FIXED = 0. A child's multiplicity = product of its ancestors' instance counts. Units: DEGREES for angleoffset, rotation, radialdirection, cant, clusterrotation, launchrodangle, launchroddirection; RADIANS for winddirection, <wind><direction>, <windlevel direction>.
- AUTO DIMENSIONS MUST BE RECOMPUTED [VERIFIED-RUN]: in 155 of 252 auto values in the samples, the number stored after 'auto' is STALE (out/stale_auto_values.txt). Example: the 24.12 'Dual parachute deployment' stores <radius>auto 0.025</radius> but OR resolves 0.028321. Rings/couplers/bulkheads/tube fins write 'auto' with no number at all. Body-tube/transition chain, a stateless re-implementation of OR's stateful refComp logic, matching OR to ≤7.7e-15 m on all 343 fore/aft radii of the 71 sample files: prev/next = adjacent symmetric component in the inline chain (same parent; across stages under the rocket). front_auto(c) [radius offered to the successor] = −1 if a transition's aft radius is auto, else its aft radius; for a body tube, if auto → front_auto(prev), else its radius. rear_auto(c) = −1 if a transition's fore radius is auto, else its fore radius; for a body tube, if auto → rear_auto(next). Transition fore auto = front_auto(prev) (0.025 if none); aft auto = rear_auto(next). Body tube auto: if prev exists and does not use its next as reference → front_auto(prev); else if next exists and does not use its prev → rear_auto(next); else 0.025. Ring outer radius auto = min(parent inner radius at the ring's front and back), clamped to [0, L_parent]; parent inner radius = r − t (body tube; 0 if filled), r(x) − t (transition, radial subtraction), r_o − t (inner tube / coupler). Centering-ring inner auto = max outer radius of axially overlapping sibling inner tubes, capped at r_o. Mass objects with packedradius 'auto <r_saved>': the packed VOLUME r_saved²·L_saved is preserved; r_auto = getMaxParentRadius (nose cone: base radius; transition: max(fore, aft); body tube: inner radius; ring: inner radius); effective L = r_saved²·L_saved / r_auto². OR QUIRK [VERIFIED-RUN]: OR positions such mass objects (MIDDLE/BOTTOM) at load time using the SAVED packedlength, but uses the recomputed length for mass. Example: Dual-parachute drogue in the 1.8 file — OR x = 0.832485 (same as using saved L) vs self-consistent 0.842976. proto_parser emulates this via EMULATE_OR_STALE_POSITION. Reference length: maximum = 2·max(fore, aft) over active symmetric components; nosecone = 2·(fore radius of the first symmetric component if ≥ 0.5 mm, else its aft radius); custom = <customreference>.
- TRANSITION / NOSE SHAPES [VERIFIED-SRC Transition.Shape; VERIFIED-RUN against OR]. Let r1 ≤ r2 (swap ends if fore > aft), L = length, k = shape parameter. Unclipped: r(x) = r1 + f(x; R = r2 − r1, L). Clipped (ellipsoid/power/haack only; nose cones never clipped): r(x) = f(c + x; R = r2, c + L), where the clip length c is found by bisection (tolerance 1e-4) so that f(c; r2, c + L) = r1. f by shape: conical f = R x/L. Ogive: if L < R, scale x by R/L and set L = R; ρ = √((L² + R²)((2 − k)²L² + k²R²) / (4k²R²)), Λ = L/k, y0 = √(ρ² − Λ²), f = √(ρ² − (Λ − x)²) − y0; conical if k < 0.001; k = 1 is a tangent ogive. Ellipsoid: x' = xR/L, f = √(2R x' − x'²). Power: f = R(x/L)^k. Parabolic: f = R(2x/L − k(x/L)²)/(2 − k). Haack: θ = acos(1 − 2x/L), f = R√((θ − sin 2θ/2 + k sin³θ)/π); k = 0 is Von Kármán, k = 1/3 is LV-Haack. Defaults: ogive 1, power 0.5, parabolic 1, haack 0.
- MASS MODEL [VERIFIED-RUN: matches OR 24.12 structure mass to ≤6.4e-6 relative and structure CG to ≤4.8e-6 m on all 212 simulation configurations; per-component mass median 6e-10]. Symmetric shells: 128 frusta. For each slice, wall height h = t·√((Δr)² + l²)/l, inner radius = max(r_o − h, 0); frustum volume V = (π/3)·l·(r1² + r1 r2 + r2²), centroid xc = l(r1² + 2 r1 r2 + 3 r2²) / (4(r1² + r1 r2 + r2²)). Shoulders are rings π(R² − (R − t)²)L_s placed before x = 0 or after x = L; a cap is a disk of radius (R − t) and thickness t at the shoulder end. Body tube: ρπ(r² − (r − t)²)L. Fins: planform area integrated between the fin outline (+ r_front) and the body surface (body sampled every 2.5 mm, max 100 divisions, if the parent is a non-conical transition or the fin is canted) with the strip formula dA = Δx(y0 + y1)/2, xc = (x0(2y0 + y1) + x1(2y1 + y0)) / (3(y0 + y1)); m = A·t·k_cs·ρ, plus tab (L_tab·h_tab·t·ρ) and fillet (cross-section 2[tanβ r_f²/2 − β r_f²/2 − α r_b²/2] with α = asin(r_f/(r_f + r_b)), β = acos(r_f/(r_f + r_b)), times root length times fillet density), all times n. Tube fins: π(r_o² − (r_o − t)²)L n ρ. Lug: Lπ(r² − (r − t)²) n ρ, cg x = L/2 + s(n − 1)/2. Rail button: π[(D/2)²h_f + (d/2)²(H − h_f − h_b) + (D/2)²h_b + ⅔(D/2)²h_s] n ρ, cg x = s(n − 1)/2. Rings: π(r_o² − r_i²) L ρ n. Mass component: mass. Shock cord: cordlength·ρ_line. Parachute: π(d/2)²ρ_s + linecount·linelength·ρ_line. Streamer: L·W·ρ_s. Mass-object cg = L/2. Overrides (MassCalculation.calculateStructure): children are computed per parent instance. overridemass sets the weight (assemblies take the children's CM as position); overridesubcomponentsmass zeroes the children's mass. overridecg puts x at x_front + overridecg; overridesubcomponentscg moves the children's CM to that x. Motors: motor front = mount x_abs + L_mount − L_motor + overhang; CM = front + motor CGx(t), which is L_motor/2 for RASP or auto-CG RSE data.
- FLIGHT CONFIGURATIONS / MOTORS / IGNITION [VERIFIED-SRC RocketSaver, MotorMountHandler, MotorHandler, MotorConfigurationHandler]. On the rocket: <motorconfiguration configid='UUID' [default='true']> (the loader also accepts <flightconfiguration>) containing an optional <name> (only if user-overridden) and <stage number='i' active='bool'/> (1.8+; if no stage is active, stage 0 is forced active). On a body tube or inner tube: <motormount> with <ignitionevent>automatic|launch|ejectioncharge|burnout|never</ignitionevent> + <ignitiondelay> (s) as the default, <overhang> (m; + = motor protrudes aft), then per configuration <motor configid> with <type>single|reload|hybrid</type>, <manufacturer>, <digest>, <designation>, <diameter>, <length>, <delay>s|none</delay> (none = plugged; missing = plugged plus a warning), and optional <ignitionconfiguration configid><ignitionevent/><ignitiondelay/>. 'automatic' = launch for the launch stage, otherwise the ejection charge of the stage below; ejectioncharge/burnout refer to the stage directly below. Motor count = cluster count × pod/parallel-stage instance counts.
- MOTOR DIGEST + RESOLUTION [VERIFIED-RUN]. 23.09/24.12 store NO thrust curve; OR resolves the motor from its bundled Java-serialized database (thrustcurves.ser, 1936 motors in 24.12), by digest first and then by type/manufacturer/designation. The digest is MD5 over big-endian int32 values: for each (order, values) block, update(order), update(len), then each round(next(next(v)·mult)) with next(v) = v + sign(v)·1e-11 and Java rounding. Blocks: (0, time s × 1000), (1, [m_launch, m_burnout] kg × 1e4) or (2, mass(t) kg × 1e4), optional (4, cg(t) m × 1000), (5, thrust N × 1000). RASP: TIME, MASS_SPECIFIC(total, total − prop), FORCE. RSE: TIME, MASS_PER_TIME (MASS_SPECIFIC if auto-calc-mass), CG_PER_TIME (unless auto-calc-cg), FORCE. Curves are first finalised: t = 0 / F = 0 added if missing, duplicates removed. motor_digest.py reproduced the stored .ork digest for all 7 of the 31 sample motors I tested (Estes A8, C6, D12; AeroTech H669N, J570W, G64W, I1299N), using files from the thrustcurve.org API (POST https://www.thrustcurve.org/api/v1/search.json, then download.json with data='file', base64). It also reproduced 4 of 5 embedded 1.11 .rse digests; the Estes A10 mismatch is unexplained. Master's MotorDigest.isDigestCompatible additionally accepts thrust-only, mass/time and cg/time variants.
- RECOVERY AND STAGING [VERIFIED-SRC]. Recovery defaults are child elements: deployevent (launch|ejection|apogee|altitude|lowerstageseparation|never; default ejection), deployaltitude (m above launch; default 200, fires when descending through it), deploydelay (s). Per-configuration overrides: <deploymentconfiguration configid> with the same children. Dual deploy = drogue 'apogee' (+ delay) and main 'altitude', e.g. 152.4 m in the Dual parachute example. Stage separation (stages > 0 only): separationevent — 24.12: launch|ignition|burnout|ejection|upperignition|altitudeascending|apogee|altitudedescending|never; 23.09: upperignition|ignition|burnout|ejection|launch|never — plus separationaltitude (24.12) and separationdelay; overrides via <separationconfiguration configid>.
- SIMULATION CONDITIONS [VERIFIED-SRC OpenRocketSaver.saveSimulation, SimulationConditionsHandler, WindHandler, AtmosphereHandler]. <simulation status=uptodate|loaded|outdated|external|notsimulated> contains <name>, <simulator>RK4Simulator</simulator>, <calculator>BarrowmanCalculator</calculator>, <conditions>, <extension extensionid><entry key type=number|string|boolean|list>* (pre-1.7: <listener>), and <flightdata>. Conditions: configid; launchrodlength (m); launchintowind (bool, 24.12; if true, rod direction = wind direction); launchrodangle (DEG from vertical); launchroddirection (DEG compass, 0 = N, 90 = E); legacy windaverage (m/s), windturbulence (σ/mean), winddirection (RAD); <wind model='average'><speed/><direction rad/><standarddeviation m/s/>; <wind model='multilevel' altituderef='msl|agl'><windlevel altitude speed direction(rad) standarddeviation/> (pink noise per level, linear interpolation, clamped outside; the block is written even when unused, so check windmodeltype); windmodeltype Average|MultiLevel; launchaltitude (m MSL); launchlatitude/launchlongitude (deg); geodeticmethod flat|spherical|wgs84 (the loader DEFAULTS TO flat when absent); <atmosphere model='isa'/> or model='extendedisa' with <basetemperature> (K) and <basepressure> (Pa); timestep (s); maxtime (s, 24.12). Wind direction convention verified from stored trajectories: direction π/2 with a vertical rod drifted every sample to −x (west), so direction is where the wind blows FROM, clockwise from north (OR calls π/2 an 'East wind').
- FLIGHT DATA [VERIFIED-SRC + RUN]. <flightdata> attributes: maxaltitude, maxvelocity, maxacceleration, maxmach, timetoapogee, flighttime, groundhitvelocity, launchrodvelocity, deploymentvelocity, optimumdelay. Summary-only flightdata (no branches) is possible. Warnings: 23.09 writes plain text; 24.12 writes <warning type=…><id/><description/><priority/><source>uuid</source><parameter/>legacy text</warning>. <databranch name types=… optimumAltitude timeToOptimumAltitude> holds <event time type [id] [source] [warnid] [cause] [eventid]/> (types: launch, ignition, liftoff, launchrod, burnout, ejectioncharge, stageseparation, apogee, recoverydevicedeployment, groundhit, simulationend, altitude, tumble, simwarn, simabort, exception) and <datapoint>csv</datapoint>, one per adaptive RK4 step (Δt observed 0.001–0.5 s). Branch 0 is the full rocket / sustainer. Booster branches start at t = 0 in 24.12 (pre-separation history copied) but at the separation time in 1.8 files. Summary derivation (FlightData.calculateInterestingValues), reproduced in 193/197 simulations: maxima over branch 0; timetoapogee = time of the FIRST sample equal to max altitude; flighttime = last time; rod / deployment (LAST deployment event) / ground-hit velocities linearly interpolated at the events; maxacceleration only BEFORE the FIRST recovery deployment. Columns are SI: angles in rad, lat/lon in deg, CP/CG in m from the nose tip, inertia in kg·m². Observed column counts: 53–54 (1.8/1.9), 58–59 (1.10), 65–70 (1.11). Extension columns appear, e.g. 'Control fin cant'.
- COLUMN-NAME LOCALISATION [VERIFIED-SRC]. In 23.09/24.12, types= holds FlightDataType.getName(), i.e. the TRANSLATED display name; 13 locale files translate them (e.g. de 'Höhe'), and the loader matches names in the current locale. 26.xx writes stable save keys (time, altitude, velocity_total, drag_coeff, cg_location, …) and also renamed some display names ('Drag coefficient (CD)'); the master loader maps all forms. The prototype maps English names, 26.xx keys and the symbol-suffixed names (TYPE_KEYS; out/flightdatatype_master.json lists 71 save keys with symbols and unit groups). After this, 0 unknown column names remain across all samples.
- STORED-DATA PRECISION [VERIFIED-SRC TextUtil.doubleToString + RUN]. 22.02, 23.09 and 24.12 write '%.3f' for 0.001 ≤ |x| < 1e4 and '%.3e' (4 significant figures) otherwise, plus '0', 'NaN', 'Inf', '-Inf'. Examples: pressure 101325 → '1.013e5' (±50 Pa); rotational inertia 0.0014 → '0.001'; CG/CP ±0.5 mm; mass ±0.5 g, so ±1 g on mass minus motor mass. Ties in rounded altitude make 'timetoapogee' re-derivation pick an earlier sample (4 of 197 cases, e.g. 7.261 vs 7.273). optimumAltitude/timeToOptimumAltitude are written at full precision. Pre-1.4 files used 5 significant figures; 26.xx writes 6 decimals. - CROSS-VALIDATION VERDICT [VERIFIED-RUN, out/crosscheck_summary.txt]. Of 212 stored simulations in the 71 files, 197 contain data. ## Risks

- The REPORT.md file was not written because the harness blocks report files from subagents; the full report content is in key_findings and verified_by_running instead, and all code and data artifacts are on disk.
- OpenRocket's auto-dimension logic is stateful (refComp, evaluation order, positions computed at load time). My stateless re-implementation matched every official sample, but pathological chains (auto↔auto↔auto with pods or parallel stages flush with the parent end, previous-component searches into child assemblies) are untested and could diverge.
- Stored 'auto <value>' caches are frequently stale (155/252). An importer that copies stored values will build wrong geometry; for example, a 0.025 m vs 0.028321 m body-tube radius in the 24.12 Dual parachute example.
- Data-column names are localised in 23.09/24.12 files saved from non-English installs. No such sample was available; a mapping table from all OpenRocket l10n files is needed, otherwise columns will be unidentified.
- Stored simulation data has only 3-decimal / 4-significant-figure precision, a random turbulence realisation and OR model artefacts (instantaneous deployment, Barrowman limits at Mach 3). Using it as truth would bias validation; it must be labelled as an OpenRocket estimate.
- Motor curves are not in 23.09/24.12 files. Resolution depends on an external motor database (thrustcurve.org snapshot or OR's Java-serialized thrustcurves.ser); the digest variants and one unexplained mismatch (embedded A10) mean a fallback by designation, with a user warning, is needed. thrustcurve.org data licensing terms are unchecked.
- Format 1.11 (OpenRocket 26.xx) is still a development target: save keys, embedded motors, shearModulus, isdrogue and auto line lengths may change before release.
- Security: ZIP entries can carry absolute paths (zip-slip) and are of arbitrary size (zip bomb). Stdlib XML does not fetch external entities but production code should use defusedxml. Values may be NaN/Inf.
- OpenRocket used as the oracle is GPLv3. Acceptable as a separate executable for private or team use per the brief, but it must not be linked into a proprietary binary if the license situation ever changes.
- The prototype's fin model ignores cant-induced root-curve offsets (≤3e-5 m CG) and fins extending beyond the parent's ends (23% mass error on one logo-rocket fin), and approximates tabs on curved bodies as rectangles.

## Open questions

- Should the product's 'OpenRocket comparison' mode reproduce OR quirks exactly (stale mass-object positions, instantaneous deployment, Barrowman) for apples-to-apples comparison, while the accuracy-first mode uses self-consistent geometry? Recommended: yes, both, with differences surfaced to the user.
- Will the product write .ork files back (export), and in which version: 1.10 for compatibility with 24.12, or 1.11 to embed motors once 26.x ships? And should the auto flags of the original be preserved on round trip?
- Motor database strategy: ship a thrustcurve.org snapshot (need to confirm licensing/terms), call the live API, or extract OR's thrustcurves.ser through a Java helper? How should the app behave when a digest has no match?
- Is a full translation table for localised databranch column names required for v1, or is English plus 26.xx save keys enough, given the team's own files?
- Why does the embedded Estes A10 curve in OR master's example not reproduce its digest (4/5 matched)? Possibly double rounding in the 3-decimal RSE writer; worth checking with OR's own isDigestCompatible before relying on embedded curves.
- Should OpenRocket headless (ORProbe approach) run only in CI as a reference oracle, or also ship as an optional bundled tool for the 'compare with OpenRocket' feature (installer size about +83 MB jar plus a JRE)?
- How should CAD-replaced components map when the user's .ork is at version 1.8 or older (no component IDs)? Tree path plus index is fragile if the user edits the rocket in OpenRocket later.
